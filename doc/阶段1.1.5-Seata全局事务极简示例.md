# 阶段 1.1.5：Seata 全局事务极简示例

## 目标
- 用最少代码演示 Seata 的全局事务（AT 模式）
- 跨服务操作：用户服务写本地表 + 钱包服务入账
- 通过 `forceFail=true` 演示回滚效果

## 演示思路
1. 在用户服务插入一条演示订单（本地事务）
2. 通过 Dubbo 调用钱包服务入账（远程分支事务）
3. 手动抛异常，验证两边数据都回滚

## 一句话说明
- 在一次请求里同时写“用户库 + 钱包库”，成功一起成功，失败一起回滚。

## 详细讲解（极简版）
1. 用户服务开启 `@GlobalTransactional`，先写本地演示订单表
2. 通过 Dubbo 调用钱包服务入账，形成跨服务分支事务
3. `forceFail=true` 时抛异常，Seata 会回滚本地订单 + 钱包入账

## 数据库准备
执行新增表（用户库）：
```sql
CREATE TABLE IF NOT EXISTS demo_seata_order (
  id BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
  user_id BIGINT NOT NULL COMMENT '用户ID',
  asset VARCHAR(32) NOT NULL COMMENT '资产类型',
  amount DECIMAL(32, 16) NOT NULL COMMENT '金额',
  remark VARCHAR(128) DEFAULT NULL COMMENT '备注',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (id),
  KEY idx_user_id (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='Seata 极简演示订单表';
```

## 代码变更
- 演示接口与服务：
  - `exchange-user` 新增 `DemoSeataController / DemoSeataService`
- 演示表与持久层：
  - `demo_seata_order` 对应实体与 Mapper

## 关键代码
1. 用户服务开启全局事务：
   - 使用 `@GlobalTransactional`
2. 先写本地表，再调用钱包服务入账
3. `forceFail=true` 时抛异常，触发全局回滚

## 接口调用示例
### 1）正常成功
```bash
curl -X POST "http://localhost:18081/api/demo/seata/execute" \
  -H "Content-Type: application/json" \
  -d '{
    "userId": 1,
    "asset": "USDT",
    "amount": 10,
    "remark": "seata-success",
    "forceFail": false
  }'
```

### 2）强制回滚
```bash
curl -X POST "http://localhost:18081/api/demo/seata/execute" \
  -H "Content-Type: application/json" \
  -d '{
    "userId": 1,
    "asset": "USDT",
    "amount": 10,
    "remark": "seata-rollback",
    "forceFail": true
  }'
```

## 验证点
- 正常成功：`demo_seata_order` 有记录，钱包余额增加
- 强制回滚：`demo_seata_order` 无记录，钱包余额不变

## 注意事项
- 两个服务必须都接入 Seata，且 `data-source-proxy-mode: AT`
- Seata Server 需正常启动，并能连接 Nacos + MySQL
- MySQL 必须存在 `undo_log` 表（Seata 初始化脚本已提供）
