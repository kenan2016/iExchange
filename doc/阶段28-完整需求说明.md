# 阶段28-完整需求说明（重写版）

## 1. 文档目的
输出一份覆盖全项目的“完整需求说明”，包含业务范围、模块职责、接口概览、数据模型、关键流程、非功能需求与待补齐项。

## 2. 项目定位与目标
### 2.1 项目定位
- 面向演示的交易所系统 Demo
- 强调流程闭环、可运行与可读性

### 2.2 项目目标
- 用户、钱包、现货撮合、行情、永续合约等主链路可跑通
- 具备多服务拆分与基础设施接入示例
- 输出阶段性文档与可视化接口

## 2.3 关键设计思路（非 CRUD）
- 撮合与行情解耦：撮合只产生成交事件，行情通过 Kafka/Disruptor 异步聚合
- 资金一致性优先：钱包资金变更落流水 + requestId 幂等 + 分布式锁
- 风险控制前置：下单/提币等关键动作在入口进行资金/风险校验
- 流程可恢复：链上充值扫描与提币回执采用“扫描+确认数”保证可追溯
- 演示与可读性优先：业务流程完整、注释充分，复杂度可控

## 3.3 需求涉及的关键技术（摘要）
- RPC：Dubbo（服务间资金操作）
- 消息解耦：Kafka（成交→行情）
- 高吞吐队列：Disruptor（撮合/行情事件串行化）
- 缓存与锁：Redis + Redisson
- 持久化：MySQL（交易/钱包），MongoDB（K 线）
- 网关鉴权：Spring Cloud Gateway + JWT
- 链上交互：Web3j（ERC20）

## 3.4 技术与需求映射（非 CRUD）
- 现货撮合高吞吐：Disruptor + 内存订单簿
- 撮合与行情解耦：Kafka 主题 `spot.trade`
- 行情实时推送：Netty WebSocket + Redis/Mongo 聚合
- 资金一致性：MySQL 流水唯一约束 + Redisson 锁
- 分布式调用：Dubbo（钱包冻结/扣减/入账）
- 链上对接：Web3j 扫描日志 + 回执确认
- 超时治理：定时任务（计划委托、资金费率、OTC 超时）
- 订单搜索：Canal 同步 MySQL → ES，查询走 ES

## 6.9 关键设计与技术落地（非 CRUD）
### 现货撮合与成交
- 撮合引擎以“价格优先/时间优先”为核心排序
- 市价单需保护价，避免吃穿盘口
- 成交结果写库后异步发送成交事件（Kafka）
- Disruptor 单线程消费撮合事件，保证顺序性与低延迟

### 行情生成与推送
- 成交事件通过 Kafka 解耦撮合与行情
- 行情服务用 Disruptor 串行化更新 Ticker/Depth/Kline
- K 线聚合支持 Redis 优先、Mongo 持久化
- WebSocket 推送按交易对/频道过滤，减少无效广播

### 钱包与资金一致性
- 并发控制：Redisson 锁按 userId+asset 粒度
- 幂等策略：requestId + 流水唯一约束
- 资金变更：先落流水再更新账户，保证可追溯

### 链上充提
- 充值：扫描 Transfer 事件 → 匹配充值地址 → 入账
- 提币：热钱包发交易 → 轮询回执 → 扣减冻结
- 归集：充值地址余额阈值归集到热钱包
- 确认数处理：避免链上重组影响

### OTC（C2C）
- 下单即冻结卖方资产，避免拒不放币
- 买方付款后进入待放币状态
- 超时自动取消/自动申诉，仲裁后放币或退款
- 放币/退款只做账本划转，不触发链上转账

### 永续合约
- 风险度与强平价基于标记价计算
- 资金费率定时计算与结算（多空资金交换）
- 全仓/逐仓逻辑分支，保证金使用规则不同

### 网关与鉴权
- 网关统一鉴权，白名单放行
- JWT 解析后透传用户身份至下游服务

### ES 订单搜索
- Canal 监听 `spot_order` / `contract_order` 变更
- ES 索引按订单类型分开，便于查询与扩展
- 查询走 ES，减少 MySQL 压力（演示）

## 9. 关键业务流程（摘要）
### 9.1 现货下单
1) 参数校验与交易对检查  
2) 钱包冻结（Dubbo）  
3) 撮合成交  
4) 扣减冻结/成交入账  
5) 成交事件发 Kafka

### 9.2 行情生成
1) Kafka 消费成交事件  
2) Disruptor 串行处理  
3) 更新 Ticker/Depth/Kline  
4) WebSocket 广播

### 9.3 合约交易
1) 校验保证金与风险  
2) 生成订单与撮合  
3) 更新仓位/保证金  
4) 资金费率定时计算与结算

### 9.4 链上充提
1) 分配充值地址  
2) 监听 Transfer 日志  
3) 入账后生成流水  
4) 提币发交易 → 回执确认 → 扣减冻结

### 9.5 OTC
1) 创建订单冻结卖方资产  
2) 买方标记付款  
3) 卖方确认或仲裁放币  
4) 超时自动取消或申诉

## 9.6 业务流程说明（详细版，非 CRUD）
### 用户登录与鉴权
1) 用户登录提交账号密码  
2) 用户服务签发 JWT  
3) 网关拦截请求校验 JWT  
4) 网关透传用户身份到下游服务

### 现货交易全链路
1) 用户提交订单（限价/市价）  
2) 交易服务校验交易对与参数  
3) 钱包服务冻结资金（Dubbo RPC）  
4) 撮合引擎执行撮合，生成成交  
5) 成交结果落库并生成手续费  
6) 钱包扣减冻结/成交入账  
7) 成交事件写入 Kafka  
8) 行情服务消费并推送 WS

### 行情聚合与推送
1) Kafka 消费成交事件  
2) Disruptor 串行处理  
3) 更新 Ticker/Depth/Kline  
4) Redis/Mongo 持久化  
5) WebSocket 按频道推送

### 合约交易与风控
1) 提交合约订单（开仓/平仓）  
2) 校验保证金与风险度  
3) 生成订单并撮合  
4) 更新仓位、保证金、手续费  
5) 强平触发定时检查  
6) 资金费率定时结算

### 链上充提闭环
1) 用户申请充值地址  
2) 监听 Transfer 日志入账  
3) 充值地址资金可选归集  
4) 用户发起提币请求  
5) 热钱包发交易并记录 txHash  
6) 回执确认后扣减冻结

### OTC 放币闭环
1) 订单创建冻结卖方资产  
2) 买方标记已付款  
3) 卖方确认或仲裁放币  
4) 超时自动取消或转入申诉
