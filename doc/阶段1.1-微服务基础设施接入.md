# 阶段 1.1：微服务基础设施接入

## 目标
- 接入 Nacos（服务注册/配置）
- 接入 Dubbo（服务间 RPC 调用）
- 接入 Sentinel（限流/熔断基础能力）
- 接入 Gateway（统一入口）
- 接入 Seata（分布式事务基础设施）
- 保留 Kafka（异步消息）作为后续业务解耦基础

## 前置条件
- 已完成阶段 1 项目骨架
- 已安装 Docker Desktop

## 目录/配置新增说明
- `infra/docker-compose.yml` 新增 Nacos、Sentinel、Seata 服务
- 各服务 `application.yml` 新增 Nacos/Dubbo/Sentinel/Seata 配置
- `exchange-gateway` 切换为 Spring Cloud Gateway
- Seata 使用 Nacos 作为注册中心与配置中心

## 步骤 1：启动基础依赖（含微服务组件）
执行脚本：
```bash
chmod +x scripts/env-up.sh
./scripts/env-up.sh
```
说明：
- 新增组件已包含在 `infra/docker-compose.yml`
- 会启动 MySQL、MongoDB、Redis、Kafka、Nacos、Sentinel、Seata

## 步骤 2：导入 Seata 配置到 Nacos
- 参考文档：`doc/阶段1.1.1-Seata客户端接入.md`
- 确保已创建 `seata-server.properties` 与 `seata-client.properties`
## 步骤 2.1：创建命名空间（可选但推荐）
- 在 Nacos 中创建命名空间（Namespace ID）：
  - `seata`：用于 Seata 配置隔离
  - `dubbo`：用于 Dubbo 元数据隔离
- 命名空间 ID 需与配置文件中一致

## 步骤 3：访问控制台
- Nacos 控制台：`http://localhost:8848/nacos`
  - 默认账号密码：`nacos/nacos`
- Sentinel 控制台：`http://localhost:8858`
  - 默认账号密码：`sentinel/sentinel`
- Seata 服务端口：`8091`（控制台端口 `7091`）

## 步骤 4：启动服务并验证注册
执行脚本：
```bash
chmod +x scripts/start-all.sh
./scripts/start-all.sh
```
检查点：
- 打开 Nacos 控制台，查看服务列表中是否出现：
  - exchange-gateway
  - exchange-user
  - exchange-wallet
  - exchange-spot
  - exchange-contract
  - exchange-market

## 本阶段产出
- 微服务基础设施运行环境（Nacos/Sentinel/Seata/Kafka）
- 网关与服务注册接入配置
- 文档（本文件）
