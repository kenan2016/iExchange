# 阶段18-合约计划委托

## 目标
- 增加合约计划委托能力：下单、撤单、查询、定时触发
- 触发后自动生成真实合约订单，保证链路完整

## 关键改动
- 新增表：`contract_plan_order`，保存计划委托数据
- 新增计划委托实体、Mapper、Service、Controller
- 新增计划委托触发调度任务
- 新增配置：`contract.plan.*`

## 表结构（核心字段）
- `action`：OPEN/CLOSE
- `side`：LONG/SHORT
- `type`：LIMIT/MARKET
- `trigger_price`：触发价
- `order_price`：委托价（市价单可为0）
- `leverage`：杠杆（开仓计划单）
- `margin_mode`：保证金模式（开仓/平仓）

## 触发规则（简化）
- 买入动作（OPEN LONG 或 CLOSE SHORT）：`markPrice >= triggerPrice` 触发
- 卖出动作（OPEN SHORT 或 CLOSE LONG）：`markPrice <= triggerPrice` 触发
- 市价计划单触发时，使用触发价作为保护价；若仍为空，则使用最新 `markPrice`

## 配置项
```yaml
contract:
  plan:
    enabled: true # 是否开启计划委托触发任务
    check-interval-ms: 5000 # 检查周期（毫秒）
```

## 接口示例

### 1) 下计划单
`POST /api/contract/plan`
```json
{
  "userId": 1,
  "symbol": "BTCUSDT-PERP",
  "action": "OPEN",
  "side": "LONG",
  "type": "LIMIT",
  "triggerPrice": 61000,
  "orderPrice": 60900,
  "quantity": 0.01,
  "leverage": 10,
  "marginMode": "ISOLATED"
}
```

### 2) 撤销计划单
`POST /api/contract/plan/cancel`
```json
{
  "userId": 1,
  "planOrderId": 1001
}
```

### 3) 查询计划单
`GET /api/contract/plan?userId=1`

## 提示
- 计划单只存条件，不参与撮合
- 触发后转成真实订单（调用合约下单服务）
- 触发失败会保留为 NEW 状态，后续可重试
