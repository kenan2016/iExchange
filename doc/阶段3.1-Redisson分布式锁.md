# 阶段 3.1：Redisson 分布式锁

## 目标
- 使用 Redisson 分布式锁应对并发写入
- 同一用户同一资产的资金变更串行化
- 保持代码简洁，幂等仍由数据库唯一索引兜底

## 前置条件
- Redis 已启动（默认 127.0.0.1:6379）

## 核心思路
1. 进入资金变更前先抢锁
2. 同一账户（userId + asset）只允许一个线程执行
3. 执行完成后释放锁

## 锁设计
锁 Key：
```
wallet:lock:{userId}:{asset}
```

锁参数（示例）：
- 等待时间：2 秒
- 租约时间：10 秒

## 代码改动
### 1）引入 Redisson 依赖
文件：`exchange-wallet/pom.xml`
```xml
<dependency>
  <groupId>org.redisson</groupId>
  <artifactId>redisson-spring-boot-starter</artifactId>
  <version>${redisson.version}</version>
</dependency>
```

### 2）配置 Redis 地址
文件：`exchange-wallet/src/main/resources/application.yml`
```yaml
spring:
  data:
    redis:
      host: 127.0.0.1
      port: 6379
      database: 0
      timeout: 2000ms
```

### 3）钱包服务增加锁封装
文件：`exchange-wallet/src/main/java/com/iexchange/wallet/service/impl/WalletServiceImpl.java`
- 所有资金变更调用 `withLock` 包裹
- 抢锁失败返回“系统繁忙，请稍后重试”

## 注意事项
- 分布式锁用于并发保护，不替代幂等
- 幂等仍由 `wallet_flow` 唯一索引兜底
- 生产环境建议评估锁粒度与超时时间
